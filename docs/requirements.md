# 相性チェッカー 要件定義書

## 1. 概要
- アプリ名: 相性チェッカー
- 形式: 開発段階はローカル実行のWebアプリ
- 将来構想: Firebaseを利用する可能性あり
- 技術スタック: Reactベース
- 目的: プログラミング学習

## 2. 利用方針
- ログイン機能は実装しない
- Waricaのようにセッション形式で利用する
- メイン画面表示前に、誰に対して点数をつけるかを選択する

## 3. 機能要件
### 3.1 デート評価入力
- 毎回のデート後に、複数項目で満足度を評価する
- 入力値は履歴として蓄積する

### 3.2 スコア計算
- 各項目について以下を計算対象とする
  - イベント重要度: 10段階評価
  - デート満足度: 1〜100点
- 累積スコアの計算式（GPA類似）
  - 分子: これまでの全イベントにおける `重要度 × 満足度` の合計
  - 分母: これまでの全イベントにおける重要度の合計
  - 結果: `分子 / 分母`

### 3.3 メイン画面
- 計算した最新の総合点を表示する
- 最新の各項目点数を5角形パラメータ表示（レーダー表示）する
- 以下の画面へ遷移するボタンを配置する
  - 点数入力画面
  - 履歴カレンダー画面
  - 設定画面
  - ヘルプ画面

### 3.4 履歴管理
- 履歴はカレンダー形式で閲覧可能にする
- 過去の点数を保存して参照できるようにする

## 4. 画面要件
- 全体で約6画面を想定
- 想定画面
  1. 対象選択画面（誰を評価するか選ぶ）
  2. メイン画面
  3. 点数入力画面
  4. 履歴カレンダー画面
  5. 設定画面
  6. ヘルプ画面

## 5. 非機能・将来拡張
- 開発初期はローカル環境で動作すること
- 将来的にFirebase連携へ移行できる構成を意識すること
